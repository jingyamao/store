# 正文与细纲版本历史设计

## 目标

每次正文或章节细纲实际改变时，保留修改前的内容；作者可以在写作台按章查看差异并恢复旧版。采用 AI 初稿、导入、CLI 修改和浏览器保存经过同一存储入口。恢复本身也保存恢复前的版本。

## 方案

选择每本书内的不可变压缩快照。每次写入前读取当前文件；内容相同则不写，内容不同则先把旧内容压缩保存在 `history/<chapter>/<text|outline>/`，然后原子写入新内容。快照文件名包含 UTC 时间、随机 ID、操作来源和完整内容哈希。首次创建文件只产生当前版本。快照只保存旧内容，因此任何覆盖都会留下可恢复的前一版。逐次快照默认不加入 Git，备份整书时须包含该目录。

比较过 Git 自动提交和增量补丁：前者会把普通自动保存混入项目代码提交；后者恢复和损坏排查更复杂。压缩快照实现简单，可直接审计和复制。后续可基于使用量增加清理策略，本阶段不自动删除版本。

## 读写与恢复

- 存储层提供列出版本、读取快照、生成逐行差异、恢复版本。只接受合法章节 ID、类型和快照 ID；读取时校验内容哈希。
- 恢复细纲前按现有 schema 校验快照；恢复正文按原样写回。恢复请求带当前文件哈希，若作者在预览后又保存了新内容则返回冲突，避免覆盖。
- 浏览器的正文保存、细纲保存、采用初稿与恢复使用同一章节锁。命令行的既有写入入口也经过版本化存储。快照创建先于覆盖，故写入中断时旧内容仍可恢复。
- 写作台增加“版本历史”面板，切换正文/细纲、查看时间与操作来源、预览逐行差异，并明确确认恢复。恢复后重新载入章节和进度。

## 验证

覆盖正文与细纲首次创建、相同内容重复保存、覆盖后的旧版列表与差异、采用初稿的来源标记、恢复后再次撤销、无效/损坏快照、浏览器过期哈希冲突和页面入口。完整测试与构建通过后提交。
